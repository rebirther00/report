## 2. 대응 논리 6장 (강도 순)

### 논리 1. RFP "등" 표현 = **예시 열거**, 모든 항목 의무 X (가장 강한 카드)

> RFP는 "유압시스템, 전동시스템, 동력시스템 **등**" 식으로 **예시 열거**한 것이지, 각 도메인을 모두 다루라는 의무가 아님. 핵심은 "주요 도메인별 물리모델을 연결한 디지털트윈 통합모델"이라는 **통합성**이지 특정 도메인 의무 포함이 아님.

### 논리 2. 다른 도메인 충분 커버로 **RFP 의도 정면 충족**

> 열거된 3개(유압·전동·동력) 중 **유압시스템·동력시스템(파워트레인)은 본 사업에서 그대로 다룸**. 추가로 MBD(기구학·동역학)·토사 반력까지 통합되어, RFP가 의도한 "주요 도메인별 물리모델 통합 = multi-physics DT" 구조는 완전히 충족.

### 논리 3. 핵심 KPI와 **인과 관계 없음**

> 본 사업 핵심 KPI 2개(물리 일치도 90% / 실차 전이 성공률 90%)는 **굴착기 단위작업의 자율작업 성능**에 직결. 자율작업 AI 정책의 입출력은 작업부 자세·관절·하중·지형이며, **동력원의 종류(전동 ↔ 내연)와는 무관**. 전동시스템 도메인 모델 부재가 KPI 달성에 영향을 주지 않음.

### 논리 4. 실증 굴착기 plant 형식과의 **물리적 정합**

> 본 사업 실차 시험은 **24톤급 굴착기(DX240)**(기존 유압·내연 양산 모델)에서 수행. 24톤급 전동식 굴착기는 국내외 양산 사례가 사실상 없어 실차에 적용되지 않으며, **실차에 없는 도메인을 시뮬레이션 모델로 따로 구축할 정당성이 약함**. 디지털 트윈은 실차와의 일치도(KPI 1)가 본질.

### 논리 5. TRL 3~5 단계 = **플랫폼 기술 개발**, 양산 다변화는 후속

> 본 사업은 TRL 3~5 — 디지털 트윈 플랫폼·AI 무인 자율작업 알고리즘의 **원천 기술 개발 단계**. 양산 굴착기의 동력원 다변화(전동·하이브리드)는 별도의 전동화 R&D 사업(예: 산업부 건설기계 전동화 사업)에서 다루는 영역이고, 본 사업이 이를 흡수하면 스코프 확장으로 핵심 목표 달성이 어려워짐.

### 논리 6. 플랫폼 **확장 가능 구조로 설계** — 영구 배제가 아닌 후속 통합

> 본 사업의 디지털 트윈 플랫폼은 **파라미터화 + 정밀도 가변 multi-physics** 구조로 설계되어, 후속 사업에서 전동시스템 도메인 모델을 동일 플랫폼에 **추가 통합 가능**. 본 사업에서 빠지는 것이 아니라, **본 사업이 후속 전동화 모델 통합의 기반 플랫폼이 되는 구조**.

## 3. 예상 질의 응답안

### Q1. RFP 개발내용에 "전동시스템"이 명시되어 있는데 본 사업에서 빠진 이유는?

→ RFP는 "유압시스템, 전동시스템, 동력시스템 **등**" 식의 예시 열거이며 모든 도메인 의무 포함은 아닙니다. 본 사업은 **유압시스템·파워트레인·MBD·토사 반력**의 4개 핵심 도메인을 통합한 multi-physics DT 플랫폼으로 RFP의 "주요 도메인별 물리모델 통합" 의도를 정면 충족합니다. 실증 굴착기가 24톤급 유압·내연 양산 모델이라는 점, 핵심 KPI 2개(거동 일치도·실차 전이 성공률)가 자율작업 성능에 직결되어 동력원과 무관하다는 점에서 전동시스템은 본 사업의 인과 경로에 포함되지 않습니다. 다만 구축할 플랫폼은 **파라미터화·정밀도 가변** 구조이므로 후속 사업에서 전동시스템 도메인 모델의 통합이 가능한 확장 구조로 설계됩니다.

### Q2. 그래도 전동 굴착기 트렌드를 고려할 때 빼는 건 너무 보수적이지 않은가?

→ 본 사업의 산출물(파라미터화 가능 multi-physics DT + AI 자율작업 정책)은 **동력원에 종속되지 않는 자산**입니다. 후속 전동화 R&D 사업이나 OEM의 전동 양산 사업에서 본 플랫폼을 그대로 활용 가능하며, 오히려 본 사업에서 자율작업 알고리즘을 동력원 독립적으로 확보하는 것이 차후 전동화 적용 시 **자산 재사용성**을 극대화합니다.

## 4. 사용 시 유의 사항

- **"예산 부족"·"인력 부족"은 절대 답변 카드로 쓰지 않기** — 평가 인상 악화
- **"등" 표현 강조**가 가장 단단한 카드 — 다른 모든 논리는 보조
- **"다른 도메인으로 충분 커버"** 답변 시 유압·파워트레인·MBD·토사 4개를 명확히 셀 수 있게 준비 (만약 컨소시엄에서 일부 안 다룬다면 답변 흔들림)

## 5. 컨소시엄 도메인 커버리지 점검

| 도메인 | RFP 명시 | 본 사업 다룸 여부 | 주관 기관 |
|---|---|---|---|
| 유압시스템 | ✓ | ✓ | 주관(심지) 또는 시뮬·CAE |
| 파워트레인 | ✓ | ✓ | 주관(심지) 또는 시뮬·CAE |
| **전동시스템** | ✓ | **✗ — 본 사업 제외** | (해당 없음) |
| MBD (기구학·동역학) | 암시 ("도메인별") | ✓ | 주관(심지) 또는 시뮬·CAE |
| 토사 반력 | ✓ (별도 명시) | ✓ | 시뮬·CAE 참여기관 (또는 주관) |
| 환경(작업환경) | ✓ | ✓ | 한건연 (DR) + 시뮬·CAE |

→ **4개 도메인 + 환경 커버 = RFP 의도 충족**. 평가위원 응답 시 본 표 활용 가능.
