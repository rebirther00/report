## 0. 사용자 구상에 대한 검토 의견 (먼저 읽을 것)

### 맞는 부분 (계획서와 정합)
- **2-track 구조(경로 계획 + 추종 제어기)**: 계획서는 "AI 정책 학습" 중심으로 서술돼 있고 저수준 제어는 "실차 센서-유압 밸브 인터페이스 매칭 등 제어 인터페이스 연동"(3차년도)으로만 언급됨. **계층 구조(고수준 정책 / 저수준 추종 제어)로 명시하는 것은 계획서와 모순 없이 오히려 서술 공백을 메워주는 좋은 프레임**임. RFP③(자율공정계획) 보강 지적과도 맞물림.
- **BC 기반 모방학습**: 계획서에 "행동 복제(BC) 등 미세조정"(3차년도) 명시. 50시간 전문가 데이터셋 보유와 직결.
- **Sim2Real = 새 기법 발명이 아니라 파이프라인 구축**: 계획서의 4중 전략(고정밀 모델·DR·System ID·실차 실증)과 정확히 일치. 정직한 프레임이라 평가 방어에 강함.
- **phase별 리워드가 다르다는 도전성 논리**: 계획서 성공 판정 기준(굴착량 버킷 80%↑ + 안전위반 없음 + 무개입 완료)과 자연스럽게 연결됨.

### 보완이 필요한 부분
1. **"작업 경로 계획"을 2계층으로 쪼갤 것.** RFP③이 "지형분석·터파기·상차경로 수립 등 자율공정계획"을 명시하고 있고, 발표자료 s47에 이미 "Unified Planner(터파기·상차) / 공정 모드(학습·지령·실행)"가 그려져 있음. 따라서 **공정 계획(작업 시퀀스, 어디를 얼마나 팔지) → 모션/경로 계획(버킷 궤적 생성)** 2계층으로 표현해야 RFP 대응과 기존 도식이 한 줄로 꿰어짐.
2. **알고리즘을 "후보 검토"로 두지 말고 "우선 적용안(선정안) + 1차년도 비교검증으로 확정"으로 서술.** 계획서에 "1차년도 RL/IL 후보군 비교·선정"이라 되어 있으므로 못박으면 계획서와 어긋나고, 비워두면 "구체성 부족" 공격을 받음. 절충: **baseline을 구체적으로 제시**하되 "1차년도 벤치마크로 확정"이라는 단서를 붙임.
3. **강화학습 XXX 채움 (권장안)**: **모방 정책을 초기 정책으로 한 PPO 미세조정 + 잔차 정책 학습(Residual RL) 병행**.
   - 근거: ETH Zurich RSL의 굴착기 자율작업(Egli & Hutter 계열)이 PPO 기반 on-policy 학습으로 실차 전이를 입증한 대표 사례 — 계획서가 이미 ETH를 벤치마크로 인용(rsl_heap)하므로 논리가 이어짐.
   - PPO 미세조정 시 **초기 정책 대비 KL 제약(또는 BC 정규화 항)**을 걸어 모방 정책 붕괴를 방지.
   - 대안 카드(질의 대비): 실차 데이터 활용 극대화가 필요하면 off-policy 계열(SAC+demonstration, AWAC/IQL)도 1차년도 벤치마크 대상에 포함.
   - 보상 설계: **phase-conditioned reward(단계별 보상 전환) + 커리큘럼 학습**, 안전·기구한계는 보상이 아니라 **제약(constrained RL / action masking)**으로 처리 — "리워드가 phase마다 다르다"는 사용자의 도전성 논리를 그대로 방법론으로 승격.
4. **제어기 XXX 채움 (권장안)**: PI+FF 기본 구조에 더해
   - **역액추에이터 모델 기반 FF**(밸브 데드밴드·유량맵·포화 보상) — DT가 정확하다는 전제를 실질적으로 활용하는 부분,
   - **외란 관측기(DOB)**로 토사 반력을 외란으로 추정·보상,
   - **학습 기반 잔차 보상(learned residual compensation)** — 유압 비선형·시변 특성으로 남는 추종 오차를 소형 NN이 보정. (ETH의 actuator network와 같은 계열이라 해외 벤치마크 인용 가능)
   - DT를 튜닝 플랜트로 사용한 **게인 자동 최적화**(베이지안 최적화 등) → "DT가 정확하면 제어기 튜닝도 가상에서 끝낸다"는 메시지로 플랫폼 가치와 연결.
5. **차별성 "특히 ~~~" 채움 (권장안)**: 아래 4가지가 계획서 근거가 있는 실탄임.
   - ① **유압계까지 포함한 고정밀 DT를 학습 환경으로 사용** — 해외 사례 다수는 단순 동역학 시뮬레이터 또는 실차 직접 학습. 유압 응답·토사 반력이 학습 단계부터 반영되는 구조는 국내 유일, 해외에서도 드묾 (s38 차별성 슬라이드와 연결).
   - ② **실측 기반 토사 반력 모델**(생기원 테스트베드 3종 + 실차 계측) 연계 — 토사 gap이 굴착 Sim2Real의 최대 난점.
   - ③ **전문가 조작 신호·조인트 각도·압력까지 포함한 30톤급 50시간 데이터셋** — GOOSE-Ex 등 공개셋은 이미지/LiDAR 위주.
   - ④ **공인기관 입회 정량 성적(성공률 90%·오차 5cm) + 데이터셋 개방·자산화** — 논문 데모 수준이 아닌 성적서 기반 검증.
6. **주의**: 제어기 상세(PI+FF, DOB 등)는 계획서에 없는 신규 서술이므로, 장표에서는 "실차 탑재·제어 인터페이스 연동(계획서 3차년도)"의 **구체화**로 포지셔닝할 것. "계획서에 없는 내용 아니냐"는 질의가 오면 "계획서의 제어 인터페이스 연동 항목의 구현 방안"으로 답변.

## 슬라이드 A — AI 학습 모델: 계층형 자율작업 아키텍처 (질문 1 대응)

**헤드 메시지(상단 1줄):**
> "공정 계획 – 모션 정책 – 추종 제어의 3계층 구조로, 모방학습으로 시작해 강화학습으로 완성한다"

**레이아웃:** 좌측 세로 3계층 블록(위→아래), 우측에 각 계층별 기술·산출물 표

| 계층 | 역할 | 적용 기술 | 근거·산출물 |
|---|---|---|---|
| ① 공정 계획 (Unified Planner) | 지형 스캔 → 작업 영역·순서 결정, 터파기·상차 시퀀스 생성, 예외처리 | 지형분석 기반 규칙+최적화, 공정 모드(학습/지령/실행) | RFP③ 자율공정계획 직접 대응, s47 도식 |
| ② 모션 정책 (AI 학습 대상) | 단위 모션(굴착·선회·상차)의 버킷 궤적·조작 신호 생성 | **모방학습(BC+HG-DAgger 계열)으로 초기 정책 → PPO 기반 강화학습 미세조정(+잔차 정책)** | 전문가 50시간 데이터셋, 1차년도 벤치마크로 확정 |
| ③ 추종 제어 | 정책이 낸 목표 궤적을 유압계가 정확히 추종 | **역액추에이터 모델 FF + PI 피드백**, 외란관측기(토사 반력 보상), 학습 잔차 보정 | 고정밀 DT에서 사전 튜닝 → 실차 게인 확정. 근거: SNU-현대두산인프라코어 RA-L 2022(38톤급, 데이터 기반 모델 역변환 FF+P 피드백, 토사 상호작용 하 추종 RMSE 2cm) |

**하단 스트립 — 학습 전략 3원칙:**
- 보상은 phase별 전환: 굴착=굴착량, 이동·선회=시간·안전, 상차=위치 오차 (phase-conditioned reward + 커리큘럼)
- 안전·기구한계는 보상이 아닌 **제약**으로 (constrained RL, 제어권 회수·강제정지 연동)
- 가상-실차 **공통 입출력 구조**(관측·행동·보상)로 설계해 전이 시 구조 변경 없음 (계획서 1차년도 명시)

**예상 반박 + 방어:**
- "왜 end-to-end로 안 하나?" → 30톤급 실차 안전과 검증 가능성 때문. 계층 분리로 각 층을 독립 검증(V&V)하고, 문제 발생 시 원인 계층을 특정할 수 있음.
- "PPO로 확정인가?" → 우선 적용안. 1차년도에 IL/RL 후보 벤치마크(계획서 명시)로 확정하되, ETH 등 검증 사례가 있는 PPO 계열을 baseline으로 시작.

## 슬라이드 B — 왜 어려운가: 굴착기 자율작업의 3대 기술 난점 (질문 1·3 연결 브릿지)

**헤드 메시지:**
> "로봇 팔의 자율화와 다르다 — 비선형 유압, 스스로 바꾸는 환경, 매번 다른 목표"

**레이아웃:** 3분할 카드(난점) → 각 카드 아래 대응 기술(우리의 답)

| 난점 | 내용 | 우리의 대응 |
|---|---|---|
| 비선형 유압 구동계 | 데드밴드·포화·펌프 유량 배분·부하 의존 응답 — 전기 모터 로봇과 달리 명령-거동 관계가 비선형·시변 | 유압계 포함 고정밀 DT로 학습 단계부터 반영 + 역모델 FF·잔차 보정 |
| 환경을 바꾸는 작업 | 굴착할 때마다 지형이 변함 → 비정상(non-stationary) 환경, 동일 상태 재현 불가 | 실측 토사 반력 모델(생기원) + DR로 지형·물성 변화를 학습 분포에 포함 |
| 매번 다른 목표·phase별 다른 성능 척도 | 터파기 깊이·상차 위치가 현장마다 다르고, phase마다 시간/굴착량/오차로 평가 기준이 바뀜 | 목표 조건부(goal-conditioned) 정책 + phase별 보상 전환·커리큘럼 |

**하단 1줄:** "이 3가지가 동시에 걸리는 중대형 건설기계 자율작업은 세계적으로도 대학·선진사가 막 진입한 영역 — 도전성의 근거이자 차별성의 원천"

*(이 장은 시간이 없으면 슬라이드 A의 하단 스트립으로 압축 가능. 단, 질의 시간 대비 백업 슬라이드로는 반드시 보유 권장.)*

## 슬라이드 C — Sim2Real: 고정밀 DT 기반 양방향 파이프라인 (질문 2 대응)

**헤드 메시지:**
> "새 기법의 발명이 아니라, 검증된 Sim2Real 기법들을 고정밀 DT 위에 폐루프로 구축한다"

**레이아웃:** 중앙에 순환 루프 도식(아래 도안 참조), 좌=Sim→Real, 우=Real→Sim, 하단=정량 로드맵 바

**Sim → Real (전이):**
1. 유압·토사 포함 고정밀 DT로 gap 원천 축소 (거동 일치도 90% 목표)
2. Domain Randomization — 조도·기상·지형·토사 물성·센서 노이즈·액추에이터 파라미터 무작위화
3. 합성 데이터 대량 학습 + **기구축 전문가 실차 데이터 50시간 기반 미세조정(BC 손실 전이학습)** — 실차 단계는 탐색형 RL 불가(안전)이므로 지도학습(BC 손실)으로 정책 가중치 소폭 조정
4. 경량화(TensorRT·양자화) 후 안전 체계(제어권 회수·강제정지) 하 단계적 실차 투입

**Real → Sim (피드백):**
1. 실차 계측 시스템(LiDAR·Camera·IMU·압력, 시간동기 로거)으로 자율작업 로그 확보
2. 가상-실제 차이 분석 → **어느 도메인(유압 응답? 토사 반력? 지각?)에서 gap이 났는지 분해**
3. 실차 계측 기반 도메인별 파라미터 보정(System ID) — 유압은 벤치시험(심지)·토사는 실측 반력(생기원)·거동은 실차(한건연)로 분해 보정, 지각 gap은 포토리얼 변환(생성형 모델)으로 대응
4. 보정된 DT에서 재학습 → 루프 반복

**하단 정량 로드맵 바:**
`3차년도: 성공률 ≥50% · 버킷 오차 ≤15cm  →  4차년도: 성공률 ≥90% · 오차 ≤5cm (공인기관 입회)`

**예상 반박 + 방어:**
- "gap이 안 줄면?" → gap을 도메인별로 분해 계측하는 체계 자체가 산출물. 유압은 벤치시험 검증 모델(심지), 토사는 실측 반력 모델(생기원)로 각 도메인 담당 기관이 보정 — 책임 경계가 곧 리스크 관리 체계.
- "실차 데이터가 부족하지 않나?" → 사전 구축 50시간 + 2~4차년도 시나리오별 추가 취득. 합성 데이터가 물량을, 실차 데이터가 보정을 담당하는 역할 분담.

## 슬라이드 D — 도전성·차별성: 세계 수준 대비 우리의 위치 (질문 3 대응)

**헤드 메시지:**
> "30톤급 중대형 굴착기의 가상학습→실차 전이 — 해외 선도그룹과 같은 문제에, 그들에게 없는 무기로 도전한다"

**레이아웃:** 상단=해외 벤치마크 3열(대학/스타트업/선진사), 하단=우리만의 4대 차별 요소

**상단 — 세계 동향 (같은 방향으로 가고 있음을 보여줌):**
| 그룹 | 사례 | 시사점 |

## 심화 Q&A 스크립트

### Q. 정밀한 DT가 있는데 왜 Model-based RL이 아니라 PPO인가?

> "Model-based RL의 이점은 세 가지 경로로 이미 흡수했습니다. ① 물리 기반 DT 자체를 모델로 사용해 그 안에서 대량 학습하고, ② Real→Sim의 System ID가 '실데이터로 모델을 개선한다'는 MBRL의 핵심 루프를 정책 쪽 모델 편향 없이 수행하며, ③ 잔차 액추에이터 보정이 국소적 학습 모델 역할을 합니다. 반면 latent 모델을 별도 학습하는 협의의 MBRL은 접촉 지배 토사 환경에서 모델 오류가 이중으로 쌓여 전이 신뢰성을 해치므로 baseline에서 제외했고, 1차년도 알고리즘 벤치마크에 비교군으로만 포함해 정량 확인하겠습니다."

- 보조 논리: MBRL의 본질 가치 = 실환경 샘플 효율인데, 고속(25배) DT + GPU 병렬 롤아웃이 그 이점을 무의미화. 정밀·저렴한 시뮬레이터의 존재는 오히려 model-free 선택의 근거.
- PPO 선정 이유 요약: ① 대규모 병렬 시뮬과 표준 조합(Isaac Lab 기본) ② clip 목적함수가 사실상 trust region → BC 초기 정책을 부수지 않고 미세조정 ③ phase 전환형 보상·커리큘럼에 안정적 ④ ETH 굴착기·사족보행 등 실차 전이 검증 이력 ⑤ 하이퍼파라미터 강건. (off-policy SAC는 Q함수 초기화 불일치로 BC 정책 파괴 위험)
- "model-based는 제어 계층에(역모델 FF), model-free는 정책 계층에" 역할 분담 프레임.

### Q. PPO가 무엇인가? (기초 확인성 질문)

> "PPO는 Proximal Policy Optimization, 2017년 OpenAI가 발표한 강화학습 알고리즘으로 현재 로봇 분야 표준입니다. 강화학습은 시행착오로 정책을 개선하는데, 한 번에 크게 바꾸면 학습이 무너지기 쉽습니다. PPO는 'Proximal(근접)'이 뜻하는 대로 매 업데이트에서 정책이 이전 정책에서 일정 범위 이상 벗어나지 못하게 제한하며 조금씩 개선합니다. 저희가 선택한 이유도 이 성질입니다 — 모방학습 초기 정책을 부수지 않고 개선해야 하는데 PPO의 보수적 업데이트가 가장 적합하고, ETH 굴착기 등 실차 전이 입증 사례가 가장 많습니다."

- 심화 대비: 새/이전 정책의 행동 확률 비율을 ±10~20%로 클리핑, TRPO의 제약 최적화를 단순 근사. on-policy = 현재 정책이 굴린 데이터로만 학습 → 데이터 소모 크지만 고속 DT 병렬 샘플링으로 상쇄.
- 비유(비전문가용): "숙련 기사에게 배운 신입이 스스로 연습하되, 한 번에 습관을 다 바꾸지 않고 조금씩 바꿔 좋아진 것만 유지하는 훈련 방식."

### Q. DAgger가 무엇인가? 왜 HG-DAgger인가?

> "DAgger는 Dataset Aggregation의 약자로, 행동 복제의 복리 오차(정책이 이탈하면 참고 데이터가 없는 문제)를 해결하는 모방학습 기법입니다. 학습된 정책을 직접 구동시켜 그 정책이 방문하는 상태에 대한 전문가 정답을 수집·집적하며 재학습합니다. 저희는 가상 환경에서 전문가 유형별 2-트랙으로 씁니다 — 스크립트 전문가(궤적 최적화)는 전 상태 자동 라벨링이 가능한 기본 DAgger, 숙련 운전자는 HG-DAgger입니다. HG-DAgger는 AI가 시뮬레이터에서 작업하는 동안 운전자가 지켜보다 위험 시점에만 조이스틱으로 개입하고 그 구간이 데이터로 쌓이는 방식으로, 사람에게 소급 라벨링을 요구하지 않아 연속 동역학 태스크에 적합합니다. 본 플랫폼의 운전자 조작 환경↔AI 학습 환경 양방향 모드 전환 기능이 이 개입 루프를 직접 지원합니다."

- 운전자 시간 병목 시: EnsembleDAgger/ThriftyDAgger(불확실성 높은 구간만 질의) 보완 카드.

### Q. 모방학습은 어디서 하나? (가상 vs 실차)

> "상호작용과 학습은 전부 가상환경에서 수행합니다. 다만 시연 데이터는 기구축 실차 50시간 데이터셋을 근간으로 하고, 가상 시뮬레이터에서 숙련 운전자 추가 시연으로 보강합니다. 실차에서는 학습하지 않고 데이터 수집과 검증만 합니다 — 30톤급 장비의 온라인 학습은 안전상 배제한 설계입니다."

- 전제 조건 연결고리: 실차 데이터로 학습한 정책이 가상에서 돌려면 관측·행동 공간 동일 필요 → 계획서 1차년도 "가상-실차 공통 입출력 구조 정의"가 이 전제.

### Q. 3차년도 미세조정이 왜 "BC 기반"인가? 그냥 전이학습 아닌가?

> "맞습니다, 본질은 전이학습입니다. 실차 단계에서는 안전상 정책이 직접 탐색하는 강화학습이 불가능하므로, 실차 로그의 상태-조작 쌍을 지도학습으로 따라가게 하는 BC 손실을 미세조정 수단으로 쓰는 것입니다. BC는 방법이고, 역할은 가상 학습 정책의 실차 도메인 적응입니다."

- 용어 층위: 전이학습/미세조정=역할(왜), BC 손실=방법(어떻게). 계획서 문구 "BC 등 미세조정"의 '등'에 offline RL(IQL 등)이 대안 카드.
- 망각 방지(질의 대비): 소량 실차 데이터 과적합 시 RL로 얻은 능력 소실 위험 → ① 작은 학습률 ② 가상 정책 대비 KL 정규화 ③ 가상 데이터 rehearsal.

### Q. System ID가 특별한 기술인가?

> "맞습니다, System ID 자체는 제어공학의 검증된 고전 기법이고 저희도 새 기법이라 주장하지 않습니다. 저희가 새로 만드는 것은 그 기법이 작동할 수 있는 조건입니다. 첫째, 유압 압력부터 6축 토사 반력까지 시간동기화된 실차 계측 체계로 식별에 필요한 데이터를 확보하고, 둘째, 가상-실차 차이를 유압·토사·거동 도메인별로 분해해 각 담당 기관이 자기 모델을 보정하게 함으로써 gap의 원인을 특정 가능하게 만들며, 셋째, 이를 재학습과 묶어 반복 루프로 돌립니다. Sim2Real 전이는 새 알고리즘보다 검증된 기법들을 정밀하게 돌릴 수 있는 파이프라인과 인프라에서 성패가 갈린다는 것이 선행 사례의 교훈입니다."

- 프레이밍 원칙: 먼저 인정하고("고전 기법 맞다") 기여를 조건 구축으로 이동 — Sim2Real 헤드 메시지("발명이 아니라 파이프라인 구축")와 일관.

### Q. 역액추에이터 모델 FF의 근거는?

- **Lee et al., "Precision Motion Control of Robotized Industrial Hydraulic Excavators via Data-Driven Model Inversion", IEEE RA-L 2022** (서울대 이동준 교수팀 + 현대두산인프라코어)
- 구조 대응: 데이터 기반 모델 역변환(입력 지연·데드존 포함 모듈형 학습 모델) FF + 비례 피드백 = 우리의 "역액추에이터 모델 FF + PI FB" 구조와 동일 계열
- 성과: 상용 38톤급, 굴착·평탄화 작업, 토사 상호작용 하 경로 추종 RMSE 2cm 미만 → 5cm 목표의 "도전적이되 비현실적이지 않음" 근거 (ETH 2cm에 국내 사례 추가)
- 오프라인 지도학습 채택 이유(장비 손상 위험)가 우리의 "실차 온라인 학습 배제" 논리와 동일
- 주의: 저자 소속은 현대두산인프라코어(현 HD현대인프라코어)로 수요기업(HD현대사이트솔루션)과 다른 법인 — "국내 산학(서울대-HD현대 계열)에서도 검증" 수준으로만 언급
- 기법 계열 구분: 역액추에이터 모델 FF = ① 고전 역밸브맵/데드밴드 보상 ② 본 논문의 데이터 기반 모델 역변환 ③ ETH actuator network를 포괄하는 계열 명칭
- 논문 위치: `11. DT/paper/2. Precision_Motion_Control_..._Data-Driven_Model_Inversion.pdf`
